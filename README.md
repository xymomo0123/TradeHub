# MOMO Finance - Stock Trading System Frontend

## 项目简介

**MOMO Finance 股票交易系统前端** 是一个基于 HTML、CSS 和 JavaScript 开发的模拟股票交易平台前端项目。

项目实现了完整的股票交易业务流程，包括用户角色管理、实时行情展示、个股详情分析、股票交易、持仓管理以及交易记录查询等核心功能。

本项目通过模拟后端接口交互，构建了一个功能完整、界面友好的 Web 股票交易系统，旨在实践现代 Web 前端开发流程，提升对前后端交互、动态数据渲染以及用户体验设计的理解。

项目为《股票交易系统》课程实验项目，综合运用了 HTML5、CSS3、JavaScript、jQuery、Chart.js 等前端技术，实现从页面设计、接口调用到业务逻辑处理的完整开发流程。

## 2. 数据缓存与涨跌幅计算

系统使用 `Map` 对象：

```javascript
previousMarketData
```

缓存股票上一次价格，用于计算实时涨跌情况。


计算公式：

涨跌额：

```
最新价格 - 前一次价格
```


涨跌幅：

```
(涨跌额 / 前一次价格) × 100%
```


每次获取最新行情后：

1. 更新股票当前价格
2. 保存到缓存
3. 下一次刷新时作为计算基准


---

## 3. 定时刷新机制


### 行情刷新

```javascript
setInterval(loadMarketData, 5000)
```


功能：

- 每 5 秒请求一次行情数据
- 自动刷新股票列表
- 更新涨跌幅


### 倒计时显示

独立计时器：

```javascript
setInterval(updateCountdown, 1000)
```


实现：

- 每秒更新倒计时
- 刷新后重新开始计时


### 个股详情刷新

个股详情页面维护独立定时器：

```javascript
setInterval(updateChart, 5000)
```


避免：

- 主页面刷新
- 图表刷新

之间产生冲突。


页面关闭时：

```javascript
clearInterval(timer)
```

释放资源。

# 遇到的问题及解决方案


## 1. fetch API 与 jQuery AJAX 混用问题


### 问题

项目开发过程中同时使用：

- 原生 Fetch API
- jQuery AJAX


导致：

- 请求方式不统一
- 错误处理逻辑不同
- 部分代码存在重复


### 解决方案

后续优化方向：

统一采用 Fetch API 或 Axios：

- 统一请求格式
- 统一异常处理
- 提升代码维护性


---

## 2. 多页面异步刷新冲突


### 问题

股票行情页面和个股详情页面均需要定时刷新：

- 主页面刷新行情
- 详情页刷新走势图


多个计时器同时运行时：

- 倒计时显示异常
- 数据刷新相互影响


### 解决方案


为不同功能设计独立定时器：


行情页面：

```javascript
marketTimer
```


个股详情：

```javascript
chartTimer
```


页面关闭或模态框关闭时：

```javascript
clearInterval(timer)
```


及时释放资源。


---

## 3. 数据加载顺序问题


### 问题

个人中心页面加载时：

用户交易记录需要股票名称信息。

但是：

- 交易记录加载速度较快
- 股票行情数据尚未完成加载


导致：

股票名称无法正确显示。


### 解决方案


使用 Promise 控制异步执行顺序：

```javascript
Promise.all([
    loadUserInfo(),
    loadMarketData()
])
```


确保：

1. 用户信息加载完成
2. 股票数据加载完成

之后再渲染交易记录。
